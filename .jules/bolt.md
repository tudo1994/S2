## 2024-05-19 - Replace lodash.merge with object spread for style merging in cells
**Learning:** `lodash.merge` is expensive when called on every render/cell creation. Merging flat style objects (like `backgroundColor`, `backgroundColorOpacity`) with conditional fills can be much faster using native object spread and nullish coalescing (`??`), especially in `@antv/s2-core` cells (`data-cell.ts`, `header-cell.ts`, `row-cell.ts`). The `getBackgroundConditionFill()` method returns an object that can contain properties like `backgroundColor`. To safely override defaults, the conditional fill properties should be used with optional chaining to prevent undefined values from overwriting if the spread order is careful. As memory instructs: "When setting plans... detail the exact code replacements intended for refactoring tasks" and "When replacing lodash.merge with object spread (...) and nullish coalescing (??), always spread the conditionally merged object first...". Wait, the memory says "always spread the conditionally merged object first". Wait, `this.conditionFill` is the conditional object. So we do `{ ...this.conditionFill, backgroundColor: this.conditionFill?.backgroundColor ?? backgroundColor }`. Wait, if `conditionFill` returns undefined it can't be spread without optional chaining.

Actually, the instruction says: "When replacing lodash.merge with object spread (...) and nullish coalescing (??), always spread the conditionally merged object first (e.g., { ...source, key: source?.key ?? fallback }). Spreading it at the end will cause any undefined values in the source to overwrite the safely coalesced fallbacks." and "do not redundantly declare the fallback properties before the spread (e.g., { backgroundColor, ...conditionFill, backgroundColor: ... }) to avoid TypeScript duplicate identifier or linting errors."

**Action:** Replace `merge({ backgroundColor, backgroundColorOpacity }, this.conditionFill)` with `{ ...this.conditionFill, backgroundColor: this.conditionFill?.backgroundColor ?? backgroundColor, backgroundColorOpacity: this.conditionFill?.backgroundColorOpacity ?? backgroundColorOpacity }`.
